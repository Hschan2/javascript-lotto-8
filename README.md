## 구현 과정 기록
### 처음부터 요구사항에만 집중해서 발생한 문제
전 미션들과 달리 시작부터 요구사항을 우선으로 생각하면서 구현을 시작했습니다. 들여쓰기, 코드 길이 제한, 메소드 역할 등 요구사항을 지키며 코드를 작성하는 과정에서 코드가 길어질수록 오히려 복잡도가 증가하고, 스스로 작성한 코드임에도 불구하고 이해하기 어려웠습니다. 그래서 진행에 어려움을 느끼게 됐고, 기존 코드를 대부분 초기화하고 다시 처음부터 시작하였습니다.   

다시 시작했을 때는 요구사항보다 우선 기능을 구현하고, 테스트를 통과하고 나서 각 메소드를 최대한 역할에 맞게 분리하고, 들여쓰기나 코드 길이를 줄이려는 시도를 진행했습니다.   

이러한 진행을 통해서 전보다 더 이해하기 쉬웠고, 그래서 더 나은 진행이 이어졌습니다. 아직 부족한 실력으로 인해 완벽도는 낮다고 생각하지만, 요구사항을 최대한 지키려는 노력으로 테스트 통과를 하였습니다. 이번 경험으로 저에게 적합한 구현 방법을 더욱 확인할 수 있었던 시간이었습니다.   

## 공통 피드백과 다른 사람들의 코드를 통해서 얻은 배움
1~2주차 공통 피드백과 몇 개의 리뷰 수가 많은 다른 지원자들의 코드를 읽어보며 많은 배움을 얻었습니다. 특히, 제가 작성한 코드와 비교하면서 부족한 점을 명확하게 파악할 수 있습니다.   

예를 들어, 기존에는 숫자나 문자를 직접 작성하는 하드 코딩 방법을 사용했다면, 이번 배움을 통해서 상수로 처리해서 공통적으로 사용되는 값들을 재사용하여 값이 변화하더라도 한 번의 수정으로 개선이 가능하다는 점을 직접적으로 배울 수 있었습니다. 이 외에도 파일 및 폴더의 생성 방법이나 역할에 따른 분리 등 여러가지 새로운 지식을 얻었습니다.   

그러나, 아직 부족한 점이 많아 이해하기 어려운 부분에 대해서는 억지로 따라서 사용하려고 하기 보다 이해할 때까지 읽고, 찾아보고, 사용해보는 것이 더 낫다는 생각을 하게 됐습니다. 이해되지 않은 채 단순히 잘해보이려는 생각에 사용하는 건 오히려 스스로 성장에 부적합한 방법이라고 생각하였으며, 현재 사용하지 않더라도 계속 보고, 학습하여 이해한 뒤 적절히 사용할 수 있도록 해야겠다는 생각을 했습니다.   

## 새로운 것의 배움
이번 미션을 진행하면서 새로운 것을 배웠습니다. 바로 Class에서의 `static` 사용입니다.   

이전까지 메소드를 사용하려면 꼭 클래스 객체를 생성해야 사용할 수 있다고 생각했고, 그렇게 사용해서 복잡한 일이 많았습니다. 그러나, `static`을 사용함으로써 객체를 생성하지 않고, 클래스로 바로 불러와서 사용할 수 있다는 점에서 전보다 더 나은 코드 작성을 할 수 있었습니다.   

그러나, 이번에는 유효성 검사에 대해서 사용했지만, 이 방법은 객체 지향에 있어서 지양되기도 하는 방법이라는 내용을 봤기 때문에 다음부터는 조심스럽게 사용해야 할 것 같습니다.   

### 아직 굉장히 부족한 실력
저번 주 미션과 이번 주 미션에서 공통적으로 요구하는 `메소드는 한 가지 역할만 해야 한다`는 부분에 대해서 아직 어려움이 있습니다.   

'이 코드가 지금 메소드에 맞는 역할을 하고 있는 건가?', '이 코드를 분리하는 게 맞는 건가?', '이 코드가 다른 일을 하는 것 같으면 무조건 다 분리해야 하는 건가?'   

여러가지 생각이 들면서 아직 한 가지 일을 한다는 기준에 대해서 아직 명확하게 파악하지 못한 부분이 굉장히 아쉽다고 생각합니다. 검색이나 다른 사람들의 코드를 보면서 조금 더 이해가 필요하며, 이를 위해 시간이 더 필요하다고 느끼고 있습니다.   

또한, 이 메소드가 이 클래스에서 구현하는 게 맞는 건지에 대해서 항상 의문을 가지고 있습니다. 아직 명확한 기준을 갖추지 못했기 때문에 '이것을 생각하면 여기에 구현하는 게 맞는 것 같은데, 저것을 생각하면 다른 곳에 구현하는 게 더 맞는 것 같기도 하다'라는 생각이 반복되어 조금 더 배움이 필요합니다.
